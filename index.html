Attribute-Based Access Control (ABAC) in Keycloak

Learn how to build fine-grained, dynamic, and context-aware security policies using user, resource, and environment attributes in Keycloak.

1. Introduction to ABAC vs RBAC

Access control is the cornerstone of modern security architecture. Traditionally, Role-Based Access Control (RBAC) has been the standard. However, as business requirements grow in complexity, RBAC's limitations become evident, giving rise to Attribute-Based Access Control (ABAC).

R

Role-Based Access Control (RBAC)

Grants permissions based on pre-defined roles (e.g., Admin, Manager, Employee). While simple to start, it leads to "Role Explosion" when you need parameters like US-Sales-Manager, EU-HR-Manager, etc.

A

Attribute-Based Access Control (ABAC)

Grants permissions based on a combination of Subject, Resource, and Environment attributes. Extremely flexible, allowing complex rules (e.g., "HR Managers can view records from the US during office hours").

The ABAC Architecture (XACML Reference Model)

Standard ABAC systems follow the XACML framework, which defines specific functional entities to separate policy definition, evaluation, and enforcement:

Note: In this setup, Keycloak acts as both the PDP (evaluating decisions) and the PAP (where you manage policies). Your client application acts as the PEP, sending tokens and intercepting traffic to enforce the decision.

2. Keycloak Authorization Services

Keycloak supports fine-grained authorization policies under its Authorization Services. This is distinct from simple client scopes and role claims. It allows you to build a true centralized PDP.

Key Components:

  • Resource Servers: The application client representing the API or service you want to protect.
  • Resources: The assets being protected (e.g., specific URLs, documents, files, or generic APIs) which can have their own custom attributes.
  • Authorization Scopes: The actions allowed on resources (e.g., read, write, delete).
  • Policies: The conditions that must be met to grant access (e.g., JavaScript scripts, time rules, role requirements).
  • Permissions: The binding elements that tie together Resources, Scopes, and Policies.

3. Implementing ABAC

To implement ABAC in Keycloak, attributes must be populated across three logical layers:

  1. Subject (User) Attributes: Defined in Keycloak on the User profiles (e.g., department, clearance_level).
  2. Resource Attributes: Defined inside Keycloak Authorization tab under Resources (e.g., department = HR, classification = Level 3).
  3. Context/Environment Attributes: Provided at runtime within the evaluation context (e.g., Client Network IP, Current Time).

JavaScript Policies: Keycloak's Dynamic Engine

To write true attribute matching rules in Keycloak, you use JavaScript Policies. These run directly on the Keycloak JVM server. Here is how Keycloak parses the attributes at runtime:

keycloak-attributes-retrieval.js 
// Fetch the context
var context = $evaluation.getContext();
// Subject attributes
var userAttrs = context.getIdentity().getAttributes();
var userDept = userAttrs.getValue('department').asString();

// Resource attributes
var resourceAttrs = $evaluation.getPermission().getResource().getAttributes();
var resourceDept = resourceAttrs.getValue('department').asString();

// Perform comparison
if (userDept === resourceDept) {
    $evaluation.grant();
}

5. Hands-on Lab: Configure Keycloak ABAC

Follow this detailed lab to set up a working Keycloak instance, configure ABAC parameters, and deploy a policy that matches user clearance to resource requirements.

Prerequisites

You need Docker and Docker Compose installed on your machine.

Step 1: Build and Start Keycloak 26 with Pre-Bundled Scripts

In Keycloak 26, the legacy upload-scripts feature is completely removed for security. JavaScript authorization policies must now be pre-packaged inside a custom provider JAR file and deployed to Keycloak's /opt/keycloak/providers/ directory, while explicitly enabling the scripts feature flag.

To automate this seamlessly without installing zip utilities locally, we use a multi-stage Docker build. Review the [Dockerfile](file:///home/wasuthep/Playground/keyclock_tuts/lab-code/Dockerfile) and [docker-compose.yml](file:///home/wasuthep/Playground/keyclock_tuts/lab-code/docker-compose.yml) provided in the lab directory:

lab-code/Dockerfile 
# Bundles policy script and META-INF descriptor into a JAR provider
FROM alpine:latest AS builder
RUN apk add --no-cache zip
WORKDIR /build
COPY abac-policy.js .
COPY META-INF ./META-INF
RUN zip -r abac-policy-provider.jar abac-policy.js META-INF

FROM quay.io/keycloak/keycloak:26.6.2
COPY --from=builder /build/abac-policy-provider.jar /opt/keycloak/providers/
ENV KC_FEATURES=scripts
RUN /opt/keycloak/bin/kc.sh build
lab-code/docker-compose.yml 
version: '3.8'

services:
  keycloak:
    build: .
    container_name: keycloak_abac_lab
    environment:
      - KEYCLOAK_ADMIN=admin
      - KEYCLOAK_ADMIN_PASSWORD=admin
    ports:
      - "8080:8080"
    command: start-dev

Compile the image and start the container by running this in your terminal:

docker-compose up --build -d
Warning on In-Memory Storage: Keycloak runs on an in-memory H2 database by default. If you stop the service using docker compose down, your realm, user attributes, and policy mappings will be deleted. To pause the container without losing your progress, run docker compose stop instead. If you have run down, you will need to re-create the realm, client, users, and resources in the Keycloak Admin Console.

Step 2: Access the Admin Console and Configure Client

  1. Open browser to http://localhost:8080 and log in with admin/admin.
  2. Create a Realm named abac-realm.
  3. Navigate to Clients and create a Client:
    • Client ID: document-service-api
    • In the Capability config section, configure:
      • Client authentication: ON (Confidential client)
      • Authorization: ON (Enables Authorization Services)
      • Direct access grants: ON (Required for resource owner password credentials flow)
  4. Click Save. You will now see an Authorization tab on the client details page.

Step 3: Setup User Attributes and Profile

Create two users to test access permissions. Due to Keycloak 26's default **User Profile** policies, basic fields must be fully completed to allow API logins without encountering "Account is not fully set up" errors.

  1. Create user: alice
    • Username: alice
    • Email: alice@example.com
    • First Name: Alice
    • Last Name: Smith
    • Email verified: Toggle **ON**
    • Required user actions: Ensure this field is **empty** (no actions like Update Password or Verify Email listed)
    • Go to the **Attributes** tab:
      • Add Attribute: Key = department, Value = hr
      • Add Attribute: Key = clearance_level, Value = 3
  2. Create user: bob
    • Username: bob
    • Email: bob@example.com
    • First Name: Bob
    • Last Name: Jones
    • Email verified: Toggle **ON**
    • Required user actions: Ensure this field is **empty**
    • Go to the **Attributes** tab:
      • Add Attribute: Key = department, Value = eng
      • Add Attribute: Key = clearance_level, Value = 1
  3. Set password credentials for both users:
    • Go to the **Credentials** tab for each user.
    • Click **Set password** (or Reset password).
    • Password: password
    • Set **Temporary** to **OFF** (this is critical for direct login API).
    • Click **Save** / **Set password**.

Step 4: Define Authorization Resources & Attributes

In Keycloak, we must define protected resources and map attributes to them.

  1. Go to Client: document-service-api -> Authorization -> Resources.
  2. Create Resource:
    • Name: Secret HR Report
    • Type: document
    • URI: /documents/hr/secret
    • Add Attributes: Key = department, Value = hr
    • Add Attributes: Key = classification_level, Value = 3
  3. Click Save.

Step 5: Register the Pre-Bundled JavaScript Policy

Because our custom policy has been packaged and registered in [keycloak-scripts.json](file:///home/wasuthep/Playground/keyclock_tuts/lab-code/META-INF/keycloak-scripts.json), Keycloak 26 makes it available in the console by default. You do not need to copy-paste code into the browser.

  1. Go to client's Authorization -> Policies -> Create Policy.
  2. Look for our pre-registered policy under the dropdown list. Select **Verify Dept and Clearance ABAC Policy** (the name matches the registry entry).
  3. Give it a local name: Verify Dept and Clearance ABAC Policy.
  4. Click Save.

Step 6: Create the Permission Binding

  1. Go to client's Authorization -> Permissions -> Create Permission.
  2. Select Resource-based Permission.
  3. Fill out:
    • Name: Secure Document Access Permission
    • Resources: Select Secret HR Report
    • Policies: Select Verify Dept and Clearance ABAC Policy
  4. Click Save.

Step 7: Testing the Policy Execution

You can verify access rights using the Keycloak Authorization Endpoint. Let's obtain an Access Token for users and request access approval.

1. Authenticate Alice (Department: HR, Clearance: 3)

# Get Access Token for Alice
curl -d "client_id=document-service-api" \
     -d "username=alice" \
     -d "password=password" \
     -d "grant_type=password" \
     -d "client_secret=<YOUR_CLIENT_SECRET>" \
     -X POST http://localhost:8080/realms/abac-realm/protocol/openid-connect/token

2. Query keycloak for Resource Authorization Decisions

# Alice requests access to "Secret HR Report" (Clearance 3 required, Dept HR required)
curl -H "Authorization: Bearer <ALICE_ACCESS_TOKEN>" \
     -d "grant_type=urn:ietf:params:oauth:grant-type:uma-ticket" \
     -d "audience=document-service-api" \
     -d "response_mode=decision" \
     -d "permission=Secret HR Report" \
     -d "network_location=office" \
     -X POST http://localhost:8080/realms/abac-realm/protocol/openid-connect/token

Response for Alice will be {"result":true} (Access Approved).

3. Repeat with Bob (Department: Eng, Clearance: 1)

When Bob requests access to the Secret HR Report, Keycloak's PDP evaluates the JS policy and returns a 403 Forbidden (Access Denied) due to both a department mismatch and insufficient clearance levels.
